## How I Approach Engineering

I try to keep the process as important as the result:

1. **Understand the use case** and identify the real engineering constraints.
2. **Build a simple, testable baseline** before adding complexity.
3. **Evaluate the result** using meaningful metrics, edge cases, and direct inspection.
4. **Integrate carefully** with clear APIs, error handling, and maintainable code.
5. **Document limitations** and distinguish completed functionality from planned work.

I use AI coding assistants such as **GitHub Copilot** and **Google Antigravity** as development aids, not as substitutes for understanding a code change. The standard I aim for is to review changes, validate assumptions, and test relevant behavior before accepting generated code.
